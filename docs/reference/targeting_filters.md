# Targeting Filters Reference

This document outlines the strict binary filters and constraints used to qualify or disqualify potential consulting leads.

## Binary Disqualifiers (Kill Criteria)
If a prospect meets any of these criteria, they are immediately disqualified.

*   **Compliance & Liability Risk:** Projects involving HIPAA (medical records), PCI (credit card processing), or highly sensitive PII.
*   **Gatekeeper Block:** The primary point of contact is not the ultimate decision-maker (e.g., Founder, Owner, Managing Partner, C-Level).
*   **Core Product Development:** The prospect wants you to build the core application they sell to their customers (high risk, 3 AM emergency liability).
*   **Vague Definitions of Done:** The project lacks a measurable, binary end-state (e.g., "Make the app faster" instead of "Reduce API response time to < 200ms").

## Qualification Criteria (Seek)
Ideal prospects should strongly exhibit these characteristics.

*   **Process vs. Product:** The request revolves around internal processes, automation, internal dashboards, or CI/CD pipelines.
*   **High Pain Tolerance for Manual Work:** The business is currently bleeding time or money due to manual data entry, disconnected systems, or brittle server deployments.
*   **Budget Floor:** Capable of meeting the minimum $1,000/month or per-project threshold.
